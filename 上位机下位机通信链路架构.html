连接 上位机侧 (Jetson)

设备节点/dev/ttyACM0 (Linux) 或对应 COM 口
波特率CDC 无物理波特率概念，上层可设任意值（实际速率由 USB HS 保证）
协议实现上位机侧需实现同一帧格式 (0xA5 0x5A ... CHKSUM)
主要发送ODOM 里程计数据 (CMD 0x01)，持续高频推送

帧 通用帧格式

Byte 00xA5 — 帧同步头 1 (RC_SYNC1)
Byte 10x5A — 帧同步头 2 (RC_SYNC2)
Byte 2CMD — 命令字，决定 PAYLOAD 语义
Byte 3-4LEN — 载荷长度，小端序 uint16，max=64
Byte 5..PAYLOAD[LEN] — 载荷数据
最后 1BCHKSUM — 校验和 = CMD ^ LEN_LO ^ LEN_HI ^ 逐字节 PAYLOAD XOR

上行 上位机 → STM32

dispatch_frame() 中处理，数据写入或触发回调

0x01 ODOM 里程计
float32[6] (x,y,z,roll,pitch,yaw) · 24字节固定
→ 写入 latest_odom 全局变量，可选触发回调
0x02 PATH 路径
uint8 n + float32[n*2] 路点数组
→ 回调 rc_set_path_callback — 无人注册
0x03 KFS KFS检测
uint8 n + [uint8 id + float32 xyz]*n
→ 回调 rc_set_kfs_callback — 无人注册
0x04 CMD_RSP 命令响应
枚举已定义，dispatch_frame 无对应 case — 死代码
0x05 ZONE_I_PATH I区路径
uint8 start,end,n + [uint8 block_id]*n
→ 回调 rc_set_zone_i_path_callback — 无人注册

下行 STM32 → 上位机

通过 send_frame() 组帧，经 upper_pc_usb_putc() 逐字节发出

0x20 DEBUG_HEADING_HOLD 航向保持调试
float32[6] (yaw_ref, yaw, err, i_term, output, yaw_rate_dps)
→ 由 chassis_heading_hold.c + yaw_heading_ctrl.c 发送
0x21 DEBUG_NAV_GOTO 导航调试
float32[6] (ex, ey, dist, zone, vy_fwd, vw_str)
→ 由 odom_nav_goto.c 发送
0x10 ACK 确认应答 · uint8 cmd + uint8 code — 全项目无调用
0x12 STATUS 状态上报 · uint8 state — 全项目无调用
0x13 ZONE_I_INFO I区KFS信息 — 全项目无调用
0x14 DOCK_OK
— 全项目无调用
0x15 GO_ZONE_I
— 全项目无调用

结构 关键 Payload 数据结构

rc_odom_tfloat32 x, y, z, roll, pitch, yaw (6×4=24B)
rc_path_tuint8 num + rc_waypoint_t points[16] (max 1+16×8=129B)
rc_kfs_tuint8 num + rc_kfs_detect_t detections[8] (max 1+8×13=105B)
rc_zone_i_path_tuint8 start,end,n + block_ids[32] (3+32=35B)
rc_debug_heading_hold_tfloat32 yaw_ref, yaw, err, i_term, output, yaw_rate (24B)
rc_debug_nav_goto_tfloat32 ex, ey, dist, zone, vy_fwd, vw_str (24B)
