📈 五、CH7 边沿检测详解

/* Motion_Task.c:84-118 — 每 tick 执行，在 switch(control_mode) 之前 */

{
    uint8_t ch7_high = (control_mode == full_auto_control) && (ch7_bit == 1u);

    /* ── CH7 下降沿 (高→低) ── */
    if ((ch7_high == 0U) && (s_ch7_prev_high != 0U))
    {
        app_zone1_mission_clear();                     // ① 清理 zone1 任务
        if (flow_mode == flow_camera_debug)             // ② 退出摄像头纠偏
            flow_mode = flow_none;
        if (app_flow_mode == app_flow_zone1)            // ③ 中断 zone1（多通道触发时）
            app_flow_mode = app_flow_none;
    }

    /* ── CH7 上升沿 (低→高) ── */
    else if ((ch7_high != 0U) && (s_ch7_prev_high == 0U))
    {
        // 检查是否有其他通道占用（CH5 非中位 / CH6 高位）
        uint8_t z1_cmd_count = (ch6==1) + (ch5_active) + 1/*CH7*/;

        if (z1_cmd_count == 1u                     // 仅 CH7 自己
            && flow_mode == flow_none              // 没有 flow 在跑
            && app_flow_mode == app_flow_none)     // 没有 zone 在跑
        {
            flow_mode = flow_camera_debug;  // ← 启动摄像头纠偏
        }
    }
    s_ch7_prev_high = ch7_high;
}
场景z1_cmd_count结果
仅 CH7 上升1→ 启动摄像头纠偏
CH7+CH6 同时上升2跳过 → 留给多通道触发 zone1
CH7+CH5 同时上升2跳过 → 留给单通道触发 get/put KFS
CH7 下降—退出摄像头纠偏 · 清理 zone1

🔄 六、full_auto_control 执行顺序

Motion_Task.c 每个 tick 按优先级从高到低检查，命中即执行：

优先级条件动作
1 app_flow_mode == app_flow_zone2 轮询 zone2 状态机 → 完成切 zone3 / 完成置 none
2 app_flow_mode == app_flow_zone1 空闲时启动 · 轮询 zone1 · 完成切 zone2 · 失败置 none
3 app_flow_mode == app_flow_zone3_prep 运行 zone3 预准备阶段 → 完成置 none
4 app_flow_mode == app_flow_zone3 运行 zone3 → 完成置 none
5 flow_mode == flow_none → 单/多通道触发入口（见第四节）
6 flow_mode != flow_none 留给 Can_Task.c 消费 · 不在此处理
⚠ 注意：zone1/zone2/zone3 在 Motion_Task 中直接运行（app_flow_mode 类型）， 而 get_kfs/put_kfs/上台阶/摄像头纠偏 在 Can_Task 中运行（flow_mode 类型）。 两者互斥 — app_flow_mode 优先级更高，会阻挡 flow_mode 的轮询入口。

🛠 十、如何修改触发

场景 1：换一个通道触发摄像头纠偏

  1. 在 Motion_Task.c:84-118 边沿检测块，把 ch7_bit 改成目标通道的 bit
  2. 在 Motion_Task.c:117 同步修改变量名
  3. Can_Task.c 不需要改

场景 2：停用摄像头纠偏（保留代码）

注释掉 Motion_Task.c:114 一行即可：

// flow_mode = flow_camera_debug;  /* 停用：CH7 上升沿不再触发 */

Can_Task.c 的 flow_camera_debug case 自然变成死代码。

场景 3：新增一个 flow_mode 类型的功能

  1. Motion_Task.h — 在 Flow_mode 枚举加一项
  2. Can_Task.c — 在 switch(flow_mode) 加 case + 处理函数
  3. Motion_Task.c — 在单通道轮询 (line 268-273) 或边沿检测 (line 84-118) 加触发映射

场景 4：新增一个 app_flow_mode 类型的功能

  1. Motion_Task.h — 在 App_flow_mode 枚举加一项
  2. Motion_Task.c — 在 full_auto_control 的 if-else 链中加新分支（在 zone3 之后、flow_mode 检查之前）
  3. 新功能的状态机 Run/Poll/IsDone 函数在 Motion_Task.c 的分支中调用
