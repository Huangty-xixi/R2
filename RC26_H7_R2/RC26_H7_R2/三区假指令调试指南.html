三区假指令调试指南

app_zone3.c · app_init.h · NEW 仿二区模式

核心思路：仿照二区 APP_ZONE2_DBG_FAKE_MISSION 模式， 新增 APP_ZONE3_DBG_FAKE_CMD 宏开关。启用后， R2 到达点1进入 wait_r1_cmd 状态时，自动按预设序列投递模拟的 R1 指令 （P2→P3→P4 放 KFS），无需真实 USART3 通信即可跑通完整三区流程。

宏名默认值说明
APP_ZONE3_DBG_FAKE_CMD 1U 总开关。设为 0 则所有假指令代码被 #if 排除，零开销
APP_ZONE3_DBG_FAKE_CMD_SEQ P2, P3, P4 预设指令序列。用枚举名，可读性好。在 Keil 可 -D 覆盖
APP_ZONE3_DBG_FAKE_CMD_COUNT 3U 序列长度。必须和 SEQ 一致，防止越界
APP_ZONE3_DBG_FAKE_CMD_DELAY_MS 2000U 回到点1后延迟多久再发下一条指令（毫秒）

使用方法 三步启动测试

1. 确认宏开关

Keil Options → C/C++ → Define 中确认（或不设，默认已启用）：

APP_ZONE3_DBG_FAKE_CMD=1

正式比赛时设为 0 或删除该宏定义，所有假指令代码不参与编译。

2. 确认点坐标

确保 g_app_zone3_cfg 中的 p1~p4 坐标与实际场地一致（默认值在 app_zone3.c 第 21-33 行）：

.p1_x_m = 0.0f,  .p1_y_m = 0.0f,   /* 等待点 */
.p2_x_m = 1.0f,  .p2_y_m = 0.0f,   /* 放KFS点2 */
.p3_x_m = 2.0f,  .p3_y_m = 0.0f,   /* 放KFS点3 */
.p4_x_m = 3.0f,  .p4_y_m = 0.0f,   /* 放KFS点4 */

3. 运行

CH8 打到 全自动，触发 Zone3 模式（CH6 或相关开关），R2 自动：

  1. 导航到 点1
  2. 等待 2 秒 → 自动模拟收到 "去点2放KFS"
  3. 去点2 → 放KFS → 返回点1
  4. 等待 2 秒 → 自动模拟收到 "去点3放KFS"
  5. 去点3 → 放KFS → 返回点1
  6. 等待 2 秒 → 自动模拟收到 "去点4放KFS"
  7. 去点4 → 放KFS → 返回点1
  8. 全部完成，停在点1

重新运行

切出全自动（CH8 离开全自动档）触发 AppZone3_Reset()，假指令计数器自动归零。重新切入即可从头开始。

与二区对比 设计理念对照
维度二区 APP_ZONE2_DBG_FAKE_MISSION三区 APP_ZONE3_DBG_FAKE_CMD
任务模型 预规划 path[] + kfs[]，一次性下发 逐条指令序列，模拟 R1 实时交互
假数据形式 path_n/path[]/kfs_n/kfs[] CMD_SEQ / CMD_COUNT / CMD_DELAY_MS
注入点 app_zone2_poll() 头部，检测无任务时自动 apply AppZone3_Run() 的 wait_r1_cmd 分支
触发时机 mission_clear 后的第一次 poll 每次进入 wait_r1_cmd 状态后延迟 2s
重置方式 mission_clear() 置 s_dbg_fake_rearm=1 AppZone3_Reset() 清零 idx 和 tick
循环/停止 单次任务，完成后 Z2_DONE 序列跑完即停，留在 wait_r1_cmd
真实数据优先级 外部 apply 覆盖假数据 cmd_pending != 0 时跳过假指令
设计要点 为什么这样做？

为什么在业务层注入而非 USART 层？

  • 改动集中：只需改 app_zone3.c，不涉及中断/USART/协议解析
  • 与二区一致：二区的假 mission 也是在 poll 中注入，不在 CAN/USART 层
  • 方便调试：直接在 wait_r1_cmd 状态内加逻辑，Watch 窗口可观察 s_dbg_fake_cmd_idx
  • 不影响真实通信：检查 cmd_pending == 0 才投递，真实 USART3 指令优先

关于 seq 序列号

假指令设置 fake_cmd.seq = idx + 1（1, 2, 3）， AppZone3_PostR1Cmd 会记录 last_seq 并过滤重复 seq。 这防止了同一个假指令被意外重复投递。

关于 fall through

假指令代码块后保留 /* fall through */ 到 on_r1_wait_cmd → done → failed → idle → break。 假指令逻辑仅在 wait_r1_cmd（地面模式）生效，在 R1 上（on_r1_wait_cmd）不触发。
