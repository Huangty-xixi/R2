1.4 正交开关：APP_ZONE1_SKILL_MODE

此宏不和比赛宏挂钩，独立控制一区内部是单圈还是双圈：

APP_ZONE1_SKILL_MODE一区行为适用场景

1双圈（抓完→转180回扫第二圈→done）Z12技能赛 / 调试双圈

二、双重控制架构

核心思路：宏在编译期分流赛制；RC 通道在运行期区分调试/比赛。

2.1 通道分配

触发方式语义受比赛宏影响？
CH7 单独一区单独调试（单圈/双圈由 APP_ZONE1_SKILL_MODE 决定）否，完全独立
CH6 单独二区单独调试否，完全独立
CH5 单独取 KFS / 放 KFS否，完全独立
CH6 + CH7 同时比赛自动序列启动是，比赛宏决定走哪条路

2.2 消抖窗口机制（500ms）

物理上 CH6/CH7 不可能瞬时同时掰到位，总是先后触发。用 500ms 消抖窗口解决：


	时间线：t=0          t=80ms        t=320ms       t=500ms
	        CH7↑         CH6↑          稳定            窗口到期
	                     cmd_count=2    cmd_count=2    → 比赛启动 ✓

	时间线：t=0          t=80ms                       t=500ms
	        CH7↑         (无变化)                      窗口到期
	                     cmd_count=1                  → 一区调试 ✓

首次检测到任意通道上升 → 开启 500ms 窗口 → 窗口内持续更新 cmd_count → 到期后按最终状态执行。先掰 CH7 还是 CH6 不影响结果，只看窗口结束时的最终状态。

2.3 Motion_Task 触发路由

/* 静态变量 */
static uint32_t s_trigger_settle_ms   = 0;
static uint8_t  s_trigger_settle_cmd  = 0;

/* flow_mode == flow_none 时执行 */
uint8_t r_zone1 = (uint8_t)(ch7_bit == 1u);
uint8_t r_z2    = (uint8_t)(ch6_bit == 1u);
uint8_t cmd_count = (uint8_t)(r_z2 + r_get_kfs + r_put_kfs + r_zone1);
uint32_t now_ms = osKernelGetTickCount();

if (cmd_count == 0u)
{
    s_trigger_settle_ms = 0;          /* 无通道 → 复位 */
}
else
{
    if (s_trigger_settle_ms == 0)
        s_trigger_settle_ms = now_ms + 500U;  /* 首次检测 → 开 500ms 窗口 */

    s_trigger_settle_cmd = cmd_count;          /* 持续更新最终状态 */

    if (now_ms >= s_trigger_settle_ms)
    {
        /* 窗口到期，按最终状态执行 */

#if APP_MATCH_IS_ARENA || APP_MATCH_SKILL_Z12 || APP_MATCH_SKILL_Z3
        if (s_trigger_settle_cmd >= 2u)
        {
            app_flow_start_match();             /* 比赛自动序列 */
        }
        else
#endif
        if (s_trigger_settle_cmd == 1u)
        {
            /* 单通道：调试模式，行为完全不变 */
            if (r_get_kfs)       flow_mode = flow_get_kfs_mode;
            else if (r_put_kfs)  flow_mode = flow_put_kfs_mode;
            else if (r_zone1)    app_flow_mode = app_flow_zone1;
            else                 app_flow_mode = app_flow_zone2;
        }
        s_trigger_settle_ms = 0;  /* 复位，等待下次触发 */
    }
}
关键保证：
  1. 比赛宏的 #if 只作用在 s_trigger_settle_cmd >= 2 分支内，单通道调试路径完全不受影响。
  2. 先掰 CH7 后掰 CH6、或先掰 CH6 后掰 CH7 —— 结果一致，500ms 窗口结束时的最终状态说了算。
  3. 单通道调试多 500ms 延迟，人手完全无感。

三、三种赛制流程

3.1 竞技赛（APP_MATCH_IS_ARENA）


CH6+CH7 → 
  一区(单圈) → 
  二区入口导航 → 地面预取 → 
  主流程(path/kfs循环) → 末桩转面 → 
  下坡 → 上坡 → 出口导航 → 
  到达 APP_ZONE2_EXIT_NAV_X/Y → DONE

二区走全程，和当前行为一致。

3.2 Z12 技能赛（APP_MATCH_SKILL_Z12=1）


CH6+CH7 → 
  一区(双圈) → 
  二区入口导航 → 地面预取 → 
  主流程(path/kfs循环) → 末桩转面 → 
  下坡 → 上坡 → DONE

二区在 下坡（下梅林）后直接结束，跳过上坡和出口导航。

3.3 Z3 技能赛（APP_MATCH_SKILL_Z3=1）


CH6+CH7 → 
  三区预备阶段 → 三区主流程(R1指令驱动)

不经过一区，不经过二区主流程。直接从预备阶段切入，绕开一区二区。

前提：遥控模式下，吸盘2已手动吸好第1个KFS。

四、三区技能赛预备阶段（app_zone3_prep）

4.1 状态机

状态说明
Z3_PREP_IDLE空闲，等待启动
Z3_PREP_WAIT_R1_UPSLOPE导航等待 1 秒，让 R1 先上坡
Z3_PREP_UPSLOPE自己上坡（Process_UpSlope）
Z3_PREP_NAV_TO_KFS2导航到第1个坐标（取第2个KFS）
Z3_PREP_GET_KFS2取第2个KFS
Z3_PREP_NAV_TO_KFS3导航到第2个坐标（取第3个KFS）
Z3_PREP_GET_KFS3取第3个KFS
Z3_PREP_NAV_TO_EXIT导航到 APP_ZONE2_EXIT_NAV_X/Y
Z3_PREP_DONE完成 → 自动调用 AppZone3_Start() 进入三区

五、二区尾段分支（竞技赛 vs Z12 技能赛）

在 app_zone2.c 的 z2_sched_last_down_dismount() 末尾：

static void z2_sched_last_down_dismount(void)
{
    /* ... 现有下坡逻辑不变 ... */

#if APP_MATCH_SKILL_Z12
    /* Z12技能赛：下梅林结束，不上坡 */
    z2_step_set(Z2_STEP_DONE, s_last_exit_pile, 0, 0, 0, 0, APP_ZONE2_FIELD_FACE_SKIP);
    s_major = Z2_DONE;
#else
    /* 竞技赛：下坡后上坡 + 出口导航（现有逻辑） */

    s_sent_upslope = 0U;
    g_process_upslope_tune.p1_x_m = PROCESS_UPSLOPE_P1_X_M;
    g_process_upslope_tune.p1_y_m = PROCESS_UPSLOPE_P1_Y_M;
    Process_UpSlope_Reset();
    z2_step_set(Z2_STEP_UPSLOPE, s_last_exit_pile, 0, 0, 0, 0, APP_ZONE2_FIELD_FRONT);
    s_major = Z2_LAST_UPSLOPE;
#endif
}

六、比赛自动序列分发

在 Motion_Task.c 或 app_flow_dispatch.c 中新增入口函数：

static void app_flow_start_match(void)
{
#if APP_MATCH_SKILL_Z12
    /* Z12技能赛：一区(双圈) → 二区(截断) */
    app_flow_mode = app_flow_zone1;

#elif APP_MATCH_SKILL_Z3
    /* Z3技能赛：预备阶段 → 三区（不走一区二区） */
    app_zone3_prep_start();
    app_flow_mode = app_flow_zone3_prep;

#else /* APP_MATCH_IS_ARENA */
    /* 竞技赛：一区(单圈) → 二区(全程) */
    app_flow_mode = app_flow_zone1;
#endif
}

七、App_flow_mode 枚举扩展

typedef enum {
    app_flow_none = 0,
    app_flow_zone1,         // 一区流程
    app_flow_zone2,         // 二区流程
    app_flow_zone3,         // 三区主流程
    app_flow_zone3_prep,    // 新增：三区预备阶段
} App_flow_mode;

八、调试方法

调试目标编译配置RC 操作
一区单圈APP_ZONE1_SKILL_MODE=0，比赛宏任意CH7 单独
一区双圈APP_ZONE1_SKILL_MODE=1，比赛宏任意CH7 单独
二区（全程）比赛宏任意CH6 单独
三区主流程比赛宏任意现有触发方式
三区预备阶段APP_MATCH_SKILL_Z3=1CH6+CH7 同时
比赛自动序列按赛制设比赛宏CH6+CH7 同时
调试原则：单通道永远是调试，比赛宏不影响单通道行为。双通道（CH6+CH7）启动比赛自动序列，由宏分流赛制。单通道触发有 500ms 消抖延迟，人手无感。
