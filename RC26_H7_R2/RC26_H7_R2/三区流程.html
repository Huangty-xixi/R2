▶ R1指令集 (USART1 + USART10)
指令ID类型说明
PUT_KFS_P21地面放KFS导航到P2，放KFS，返回P1
PUT_KFS_P32地面放KFS导航到P3，放KFS，返回P1
PUT_KFS_P43地面放KFS导航到P4，放KFS，返回P1
STOP_ACTION4中断立即中断当前动作，返回P1等待
UP_R15上R1上台阶到R1，举升到p4，等待指令
PUT_KFS_ON_R16R1上放KFS仅在R1上有效，直接放KFS
seq 去重：相同 seq 号的重复指令被忽略。STOP 通过独立 stop_pending 通道投递，优先级最高。

▶ 关键机制
机制说明
STOP优先每帧 Run() 先检查 stop_pending，通过独立通道投递，不受 seq 去重影响，中断任何当前动作
seq去重R1指令带 seq 号，相同 seq 的重复指令被忽略，避免重复触发
指令状态门控app_zone3_state_accepts_normal_cmd() 只在 idle/entry_nav/wait_r1_cmd/return_point1/on_r1_wait_cmd 接受新指令
odom保护导航状态(entry_nav/nav_to_put/return_point1/stop_nav)中 odom 无效 → 立即 failed
PutKFS兼容地面放KFS完成后自动返回P1；R1上放KFS完成后留在R1等待
全场超时action_timeout_ms=60000 每阶段独立超时，超出 → failed

▶ 调度集成 Motion_Task.c
Zone3 在 full_auto_control 每帧轮询，位于 Zone2 处理之后：
// Motion_Task.c full_auto_control 分支
if (app_flow_mode == app_flow_zone2) {
   app_zone2_poll(); ...
}
else if ((app_flow_mode == app_flow_zone3) || (AppZone3_IsActive() != 0U))
{
   // 外部激活时自动同步 app_flow_mode
   if (app_flow_mode != app_flow_zone3)
     app_flow_mode = app_flow_zone3;
   AppZone3_Run(); // 每帧驱动状态机
   if ((AppZone3_IsActive() == 0U) &&
     ((AppZone3_IsDone() != 0U) || (AppZone3_IsFailed() != 0U)))
     app_flow_mode = app_flow_none; // 结束退出
}
调度要点：
1. AppZone3_IsActive() 为真时即使 app_flow_mode 未设置也会进入轮询（支持外部 PostR1Cmd 激活）
2. AppZone3_Run() 内部首帧自动调用 app_zone3_start_core() 导航到P1
3. done/failed 后 app_flow_mode = app_flow_none，释放控制权
