🔑 为什么需要两个 AA..BB 帧？
帧 #1：一区 state 6 调用 R1Link_ClearNewMission() 消费 → s_has_new=0 — 帧被当成"释放信号"用掉了
帧 #2：二区 R1Link_TakeAndApply() → R1Link_TakeMission() 检查 s_has_new==1 才取数据

💡 两帧可以内容相同（R1 MCU 重发同一份 path+kfs），也可以帧 #2 携带更新后的任务。

🎯 motion_poll_zone1() — 一区驱动 + 切二区

static void motion_poll_zone1(void)
{
    if (!AppZone1_IsBusy() && !AppZone1_IsDone() && !AppZone1_IsFailed())
        AppZone1_Start();                    // 首次: 启动一区

    app_zone1_poll();                            // 每周期: 推进状态机

    if (!AppZone1_IsBusy() && (AppZone1_IsDone() || AppZone1_IsFailed()))
    {
        if (s_match_auto_active)                 // 比赛模式
            app_flow_mode = app_flow_zone2;  // 🔑 自动切二区!
        else
            app_flow_mode = app_flow_none;       // 手动触发: 回 idle
    }
}

🎯 motion_poll_zone2() — 二区驱动

static void motion_poll_zone2(void)
{
    if (R1Link_HasNewMission()) { R1Link_TakeAndApply(); }  // 有 AA..BB → 装载任务
    app_zone2_poll();                                // 推进梅花桩
    if (app_zone2_is_done()) {
#if APP_MATCH_IS_ARENA
        AppZone3_Start(); app_flow_mode = app_flow_zone3;  // 竞技赛 → 三区
#else
        s_match_auto_active = 0U;                          // 技能赛 → 结束
        app_flow_mode = app_flow_none;
#endif
    }
}

步骤发生位置操作s_has_news_last_mission
1️⃣ 帧到达 r1_link.c:137 r1_link_on_mission_frame decode → 写入 s_last_mission = 1 已更新
2️⃣ 一区检测 app_zone1.c:1220 poll_r1_release_sig R1Link_HasNewMission()=true → r1_pending=1 = 1 保持不变
3️⃣ 一区消费 app_zone1.c:1429 wait_r1_release R1Link_ClearNewMission() = 0 保持不变
4️⃣ 一区结束 app_zone1.c:1484 state_done active=0, done=1 → Motion_Task 切 zone2 = 0 —
5️⃣ 二区检查 Motion_Task.c:134 motion_poll_zone2 R1Link_HasNewMission() → false! = 0 有数据但取不出
6️⃣ 帧 #2 到达 r1_link.c:137 r1_link_on_mission_frame decode → 覆盖 s_last_mission = 1 已更新
7️⃣ 二区消费 r1_link.c:245 R1Link_TakeAndApply TakeMission → app_zone2_mission_apply = 0 —
⚠️ 关键洞察：帧 #1 的 path+kfs 数据在步骤 1 写入 s_last_mission，步骤 3 只清了 s_has_new 标志，数据还在。但 R1Link_TakeMission() 检查的是 s_has_new，所以二区取不到。帧 #2 覆盖 s_last_mission 后，二区才能取出。

💡 如果 R1 MCU 在帧 #1 被消费后立刻发帧 #2（同一份数据），二区拿到的就是同样的任务。
