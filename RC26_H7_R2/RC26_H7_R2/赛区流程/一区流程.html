🔍 [3] shift_right_monitor — 扫矿监控

项目内容
每帧 run_grab_monitor() 核心逻辑：
· 夹爪 idle→closing 检测 → latch → 进clamp_wait
· 视觉Y坐标在 [y_lo, y_hi] 区间: 累计stable_ticks，允许自动夹取
· 超出上/下界: flip扫方向 + pull_back减速

· Y区带滞回(6区: below/lo_band/mid/hi_band/above + unknown)
✅ 成功夹爪 latch → ④ clamp_wait
⏱ 超时15s: FLOW_THROUGH=1→跳过进⑤ | FLOW_THROUGH=0→abort

核心代码

// 配置定义 (app_zone1.h)
uint32_t dock_timeout_ms;  /* 一区全局超时(ms), 默认120s */

// 启动初始化 (AppZone1_Start)
g_app_zone1_ctx.dock_deadline_ms = now_ms + g_app_zone1_cfg.dock_timeout_ms;  // 120s

// 每帧检测 (AppZone1_Run 开头，状态机switch之前)
if (g_app_zone1_ctx.dock_deadline_ms != 0U &&
    now_ms > g_app_zone1_ctx.dock_deadline_ms &&
    g_app_zone1_ctx.state != app_zone1_state_wait_r1_release &&  // 排除已在等待
    g_app_zone1_ctx.state != app_zone1_state_done &&             // 排除已完成
    g_app_zone1_ctx.state != app_zone1_state_abort)              // 排除已中止
{
    Process_Flow_ClearChassisOverride();
    odom_nav_goto_disarm();
    YawHeadingCtrl_ParallelLegSettleReset();
    g_app_zone1_ctx.r1_wait_start_ms = now_ms;   // 5s重新计时
    g_app_zone1_ctx.r1_pending = 0U;
    app_zone1_flow_enter_state(app_zone1_state_wait_r1_release, now_ms);
}

全局超时 vs 局部超时

维度局部超时（各状态独立）V6 全局超时保底
超时值6s~30s120s (2min)
触发位置各状态 case 内部状态机 switch 之前
触发效果大部分→abort→ wait_r1_release → 松爪 → done
覆盖范围单个状态所有非终态 (1-6, 9)
设计目标状态级正常容错最后安全网: 确保永远不卡死
安全设计原则：
1. 保守默认值（120s）：远大于正常耗时(30-60s)，仅系统级异常时触发
2. 非破坏性：不走abort(不设failed)，走标准松爪→done，后续zone2正常执行
3. 不影响正常流程：正常流程远快于120s，保底完全不介入
4. 可观测：dock_deadline_ms 可在Keil Watch中实时观察倒计时
📡 R1任务帧触发与消费 V5双重防重复
V4遗留问题：AA..BB帧消费后 s_has_new 未清除 → zone1 abort重启后误判"新任务"。
V5: z1_mission_handled + R1Link_ClearNewMission 双重解决。
第1层守卫 — z1_mission_handled (局部)：
if (R1Link_HasNewMission() && z1_mission_handled==0) → r1_pending=1
第一圈消费后=1 → 不再触发；第二圈开始前清零 → 允许再次触发

第2层守卫 — R1Link_ClearNewMission (全局)：
wait_r1_release 退出时调用 → s_has_new=0
即使 z1_mission_handled 意外清零，s_has_new 也已清除

🐛 已知问题与边界情况
HIGH — wait_r1_release内+超时宏=0仍可能卡死
V6全局超时已排除wait_r1_release状态。若进入wait_r1_release后超时宏关闭且R1不来，仍可能卡死。
缓解：确保WAIT_R1_TIMEOUT_ENABLE=1(默认) / R1配合 / CH7下降沿手动mission_clear。
FIXED in V6 — FLOW_THROUGH=0灰色卡死不再永久锁死
V6 120s全局超时不分FLOW_THROUGH，到期一律强制跳转。
MEDIUM — 2min保底可能过早打断第二圈
第一圈耗时接近120s时，第二圈可能无时间执行。可通过增大dock_timeout_ms缓解。
MEDIUM — NotifyDockOk + ClampHeadCtrl_Init 冲突（同V5）
wait_r1_exit中先NotifyDockOk(舵机→upright)立即又Init(舵机→mid)，逻辑冗余但无实际损害。
MEDIUM — 第二圈clamp后也回返点（同V5）
V5/V6第二圈走advance_turn180回return_target再等R1超时done。若赛规不要求回返点需修改分支。

影响有限，有V5守卫和V6保底兜底。
