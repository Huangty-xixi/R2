🔧 R2 重试机制设计方案

适用比赛：技能赛 Z12 · 技能赛 Z3 · 竞技赛 (Arena)  |  触发通道：CH5（s_match_auto_active=1 后启用）

一、重试类型概览

类型CH5 操作第一次脉冲（中断）第二次脉冲（重启）
武馆重试 最大 → 回中 中断当前流程，保留吸盘/KFS/任务数据 一区已完成→启动二区；一区未完成→启动一区
对抗区重试 最小 → 回中 中断当前流程，保留吸盘/KFS/任务数据 从三区预备 P1 导航开始 → 等待 R 命令

门控规则

  • 空闲时收到脉冲 → 忽略
  • ARMED 状态收到反方向脉冲 → 忽略
  • ARMED 状态下 motion_route_channels() 被屏蔽，防止其他通道误触发
  • 50ms 边沿防抖

Process_GetKFS_AbortAndRollback()

变量回滚动作原因

sucker1_state 恢复到 idle 时的值
start_three_pos=p1/p2/p3 → 设为1；p4 → 保持0		 spin_front_to_p1 时 sucker1 被关了（吸盘不能关）

kfs_below_position → kfs_below_cmd_stop 停下轴，重启后调度器会重新设

s_get_kfs_busy → 0
s_get_kfs_chassis_fwd_done → 0

✅ 三轮 GetKFS 通用 —— start_three_pos 自动适配每轮的起始位置

3.3 重置进程 & 清理

必须停掉

  • Process_Flow_ResetAll()
  • Process_Flow_ClearChassisOverride()
  • odom_nav_goto_disarm()
  • YawHeadingCtrl_Clear()
  • ClampHeadCtrl_Init()
  • CameraCorrect_Reset()
  • 清理 zone1 / zone3 任务
  • flow_mode = app_flow_mode = none

必须保留（不动）

  • ✅ sucker1~4_state（吸盘）
  • ✅ three_kfs_position（KFS槽位）
  • ✅ main_lift_position（升降台）
  • ✅ kfs_spin/below_position
  • ✅ s_mission / s_has_mission（二区任务）
  • ✅ g_z3.last_seq（R1命令序号）

⚠ 执行顺序关键

必须在 Process_Flow_ResetAll() 之前调用 Process_GetKFS_AbortAndRollback()， 否则 ResetAll 会清零 get_kfs_step，丢失 start_three_pos 信息。

四、重启流程

4.1 武馆重试重启

第二次 CH5 max→mid 脉冲
zone1 已完成
↓
恢复 kfs_done_mask
保留 three_kfs_position
从 Z2_ENTRY_NAV 开始
zone1 未完成
↓
AppZone1_Start()
一区从头开始

二区重启详情

  1. 调用 app_zone2_reset_for_retry(saved_kfs_done_mask)
  2. 该函数重置所有执行标志（s_sent_mount, s_nav_leg_running, s_face_dir_step_done 等）
  3. 设置 s_major = Z2_ENTRY_NAV —— 从入口导航重新走完整路径
  4. s_kfs_done_mask = saved_mask —— 调度器自动跳过已完成桩
  5. s_path_idx = 0 —— 从 path 数组第一个桩开始
  6. s_mission / s_has_mission 不变 —— 保留原始任务数据
  7. 设置 app_flow_mode = app_flow_zone2

4.2 对抗区重试重启

第二次 CH5 min→mid 脉冲
→
AppZone3Prep_StartFromP1()
→
导航到 P1
(2.42, 11.64)
→
AppZone3_Start()
进入 wait_r1_cmd
等待 R1 指令

AppZone3Prep_StartFromP1() 实现要点

  • ⚠ 跳过 upslope 阶段（车已在地面）
  • 直接设置 g_prep.state = app_zone3_prep_state_nav_to_p1
  • 导航目标：P1 (2.42, 11.64)
  • 到位后调用 AppZone3_Start() → 进入 entry_nav→wait_r1_cmd

六、CH5 功能切换

条件CH5 低位CH5 高位
s_match_auto_active == 0（比赛未激活） TRIG_GET_KFS（取桩） TRIG_PUT_KFS（放桩）
s_match_auto_active == 1（比赛已激活） 对抗区重试脉冲 武馆重试脉冲

比赛通过多通道组合触发 app_flow_start_match() 进入， 此时 s_match_auto_active = 1，CH5 自动切换为重试功能。

        uint8_t ch5_bit = rc_bit_minmax_decode(RCctrl.CH5);

#endif

}

十二、违规边界检查

✅ 正常场景

  • 中断在 GetKFS 内部 → AbortAndRollback 回滚
  • 中断在导航中 → odom_nav_goto_disarm 立即刹停
  • 中断在 zone3 等待R命令 → 清除 pending cmd，保留 last_seq
  • 中断在 zone2 ENTRY_NAV → s_major 保留，重启时显式设回
  • 吸盘在 GetKFS idle 时开了 → 回滚后保持开
  • 吸盘在 GetKFS spin_to_p1 时被关了 → 回滚恢复开

🚫 极端场景

  • 紧急停止 (CH8) 在 ARMED 期间 → 正常急停流程，关吸盘，清重试状态
  • 切遥控模式 (CH8) 在 ARMED 期间 → 正常切遥控，清重试状态
  • ARMED 状态多次脉冲 → 第二次以后忽略
  • 连续快速拨 CH5 → 50ms 防抖屏蔽重复触发
  • 上下桩过程中重试 → 用户说不会在这里重试
