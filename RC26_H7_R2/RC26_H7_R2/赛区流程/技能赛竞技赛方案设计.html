二、双重控制架构

核心思路：宏在编译期分流赛制；RC 通道在运行期区分调试/比赛。

2.1 通道分配

触发方式语义受比赛宏影响？
CH7 单独一区单独调试（单圈/双圈由 APP_ZONE1_SKILL_MODE 决定）否，完全独立
CH6 单独二区单独调试否，完全独立
CH5 单独取 KFS / 放 KFS否，完全独立

2.2 Motion_Task 触发路由（全部立即响应）

uint8_t r_zone1 = (uint8_t)(ch7_bit == 1u);
uint8_t r_z2    = (uint8_t)(ch6_bit == 1u);
uint8_t cmd_count = (uint8_t)(r_z2 + r_get_kfs + r_put_kfs + r_zone1);

if (cmd_count == 0u)
{
    s_trigger_settle_ms = 0;
}
else if (cmd_count == 1u)
{
    /* 单通道：立刻执行 */
    s_trigger_settle_ms = 0;

    if (r_get_kfs != 0u)
        flow_mode = flow_get_kfs_mode;
    else if (r_put_kfs != 0u)
        flow_mode = flow_put_kfs_mode;
    else if (r_zone1 != 0u)
        app_flow_mode = app_flow_zone1;
    else
        app_flow_mode = app_flow_zone2;
}
#if APP_MATCH_IS_ARENA || APP_MATCH_SKILL_Z12 || APP_MATCH_SKILL_Z3
else
{
    /* 多通道：比赛自动序列，立刻启动 */

#endif
全部立即响应，零延迟：
  1. cmd_count == 1 → 单通道立刻执行（取KFS/放KFS/一区/二区）
  2. cmd_count >= 2 → 比赛立刻启动
  3. 比赛宏的 #if 只作用在 cmd_count >= 2 分支内，单通道不受影响

3.1 竞技赛（APP_MATCH_IS_ARENA）V7


  CH6+CH7 → 
    一区(单圈) →
    二区(入口导航 → 地面预取 →
    主流程(path/kfs循环) → 末桩转面 →
    下坡 → 上坡 → Z2_DONE)
    →
    AppZone3_Start() →
    三区entry_nav（P1导航 + ⚡并行转向 + 途中收R1命令）→
    📍P1 →

V7 变化：二区上坡后不再走出口导航，直接 Z2_DONE。由 AppZone3_Start() 接管，启动三区 entry_nav 导航到 P1（并行转向 + 途中收命令）。

3.2 Z12 技能赛（APP_MATCH_SKILL_Z12=1）


CH6+CH7 → 
  一区(双圈) →
  二区入口导航 → 地面预取 →
  主流程(path/kfs循环) → 末桩转面 →
  下坡 → 上坡 → DONE

二区在 下坡（下梅林）后直接结束，跳过上坡和出口导航。

3.3 Z3 技能赛（APP_MATCH_SKILL_Z3=1）V7


CH6+CH7 → 
  三区预备阶段 →
  等待R1上坡 → 自己上坡 →
  📍G1（预取KFS#1） →
  📍G2（预取KFS#2） → 预备阶段 DONE
  →
  三区entry_nav（P1导航 + ⚡并行转向 + 途中收R1命令）→
  📍P1 →
  三区主流程(R1指令驱动: 取KFS/放KFS/上R1)

不经过一区，不经过二区主流程。从预备阶段直接切入。

V7 调整： 预备阶段在结束前预取 G1→G2 两个桩的KFS（使用 APP_ZONE2_GET_KFS_GROUND），然后进入 Zone3 主流程的 entry_nav。entry_nav 导航到 P1 的同时⚡并行转向（蓝→场右 / 红→场左），途中可接收R1命令。

static void z2_sched_last_down_dismount(void)
{

上坡完成后 z2_sched_last_upslope() 直接设 s_major = Z2_DONE：

六、比赛自动序列分发

在 Motion_Task.c 中，通过 s_match_auto_active 标志区分调试和比赛：

static uint8_t s_match_auto_active = 0U;  // 比赛自动序列标志

static void app_flow_start_match(void)
{
    s_match_auto_active = 1U;  // 标记：自动序列进行中

#if APP_MATCH_SKILL_Z12
    /* Z12技能赛：一区(双圈) → 二区(截断) → 结束 */
    app_flow_mode = app_flow_zone1;

#elif APP_MATCH_SKILL_Z3

    app_zone3_prep_start();
    app_flow_mode = app_flow_zone3_prep;

#else /* APP_MATCH_IS_ARENA */
    /* 竞技赛：一区(单圈) → 二区(全程) → 三区(entry_nav) */
    app_flow_mode = app_flow_zone1;
#endif
}
自动衔接逻辑：
触发点条件行为
Zone1 完成s_match_auto_active==1自动启动 Zone2（竞技赛 & Z12）
Zone1 完成s_match_auto_active==0停止（调试模式）
Zone2 完成APP_MATCH_IS_ARENA自动 AppZone3_Start() → entry_nav(P1导航+⚡转向+途中收命令)
Zone2 完成APP_MATCH_SKILL_Z12停止，s_match_auto_active=0

8.2 途中命令处理逻辑

命令行为说明
PUT_KFS_P2/P3/P4直接切换导航到放KFS目标点使用 app_zone3_begin_nav_keep_vx() 不打断正在进行的 VX 转向
GET_KFS_G1/G2直接切换导航到取KFS目标点同样使用 begin_nav_keep_vx，保持 VX
UP_R1设 up_r1_deferred = 1，继续到 P1延迟执行：到达 P1 后自动触发上 R1 流程

8.3 核心代码

case app_zone3_state_entry_nav:
{
    /* 优先处理途中 R1 命令 */
    if (app_zone3_take_normal_cmd(&cmd) != 0U)
    {
        switch (cmd.id)
        {
            case APP_Z3_CMD_PUT_KFS_P2:
            case APP_Z3_CMD_PUT_KFS_P3:
            case APP_Z3_CMD_PUT_KFS_P4:
                /* 直接切换导航到放KFS点，保持VX */
                main_lift_position = main_lift_p4;
                kfs_spin_position = kfs_spin_p2;
                app_zone3_begin_nav_keep_vx(x_m, y_m,
                    app_zone3_state_nav_to_put, now_ms);
                break;

            case APP_Z3_CMD_GET_KFS_G1:
            case APP_Z3_CMD_GET_KFS_G2:
                /* 直接切换到取KFS，保持VX */
                main_lift_position = main_lift_p2;
                app_zone3_begin_nav_keep_vx(x_m, y_m,
                    (cmd.id == G1) ? nav_to_g1 : nav_to_g2, now_ms);
                break;

            case APP_Z3_CMD_UP_R1:
                g_z3.up_r1_deferred = 1U;  /* 延迟到 P1 执行 */
                break;
        }
        break;
    }

    nav_rc = app_zone3_nav_peek();
    if (nav_rc == ARRIVED)
    {
        if (g_z3.up_r1_deferred != 0U)
        {
            /* 到达 P1 后执行 UP_R1 */
            g_z3.up_r1_deferred = 0U;
            main_lift_position = main_lift_p4;
            kfs_spin_position = kfs_spin_p3;
            flow_mode = flow_up_r1_mode;
            app_zone3_enter_state(up_r1_climb, now_ms);
        }
        else
        {
            /* 正常等待 R1 命令 */
            app_zone3_enter_state(wait_r1_cmd, now_ms);
        }
    }
}

8.4 begin_nav vs begin_nav_keep_vx V7

函数行为适用场景
app_zone3_begin_nav()clear_motion（清chassis override + disarm nav）→ set_target正常状态切换（抵达后进入下一导航段）
app_zone3_begin_nav_keep_vx() 🆕仅 set_target，不清除 chassis override 和 VX 方向entry_nav 途中 PUT/G1/G2 命令切换，不打断 YawHeadingCtrl 的 VX 转向
static void app_zone3_begin_nav_keep_vx(float x_m, float y_m,
    app_zone3_state_t nav_state, uint32_t now_ms)
{
    /* 只更新目标，不清 chassis override 和 YawHeadingCtrl 的 VX */
    odom_nav_goto_set_target(x_m, y_m);
    g_z3.nav_x_m = x_m;
    g_z3.nav_y_m = y_m;
    g_z3.nav_session_id = odom_nav_target.session_id;
    app_zone3_enter_state(nav_state, now_ms);
}
